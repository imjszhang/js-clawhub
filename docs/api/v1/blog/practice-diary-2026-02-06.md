
# 从脚本触发到自主进化：构建无人值守的 Agent 闭环

> Day 7 · 2026-02-06

今日的核心任务是解决素材规模指数级增长带来的手动处理瓶颈，我将系统从“被动响应”推向“主动进化”，通过外部脚本接口与定时调度机制，实现了知识产出流程的无人值守闭环。

## 构建五层抽象网关基石，实现架构的彻底分层与解耦

面对日益复杂的自动化需求，我首先确立了以 Gateway 为核心的五层抽象架构，将底层基础设施与上层业务逻辑物理隔离。在今天的实践中，我利用 `openclaw agent` 命令行工具和 `POST /hooks/agent` HTTP 接口，成功将外部脚本（如 GitHub Actions 和 Shell 脚本）与内部 AI 推理引擎解耦。通过配置 `sessionKey`（如 `hook:github:pr-123`），我为每个外部触发源创建了独立的会话上下文，既复用了多轮对话能力，又避免了主会话的状态污染。这种分层设计不仅屏蔽了 `curl | bash` 管道执行的安全风险，更为后续引入 OADA（观察 - 分析 - 决策 - 执行）自主进化闭环提供了标准化的接入接口，让外部系统能像调用普通 API 一样触发复杂的 Agent 策略。

## 部署双 Cron 分段驱动与 inbox/batch 轮转机制，达成全链路无人值守闭环

为消除人工干预断点，我部署了基于双 Cron 的分段驱动机制。利用 `openclaw cron add` 命令，我配置了两类任务：一类是 `sessionTarget: main` 的系统事件注入（如每日清晨 06:00 的 `systemEvent` 唤醒），用于维持主会话心跳；另一类是 `sessionTarget: isolated` 的独立 Agent 运行（如每 4 小时一次的 `agentTurn`），专门处理批量吞吐任务。配合 `inbox` 到 `batch` 的状态轮转逻辑，系统现在能自动将散乱的时间线笔记转化为结构化知识资产。例如，我设置了一个名为“每日早报”的 Cron 任务，它在每天 7 点自动运行隔离 Agent，整理过去 24 小时的重要更新并投递到 Slack 频道，真正实现了从采集、处理到产出的全流程自动化。

## 执行严格审批、权限收紧及记忆职责剥离，构筑纵深安全防御体系

在推进自动化的同时，我严格执行了纵深安全防御策略，防止 Agent 在进化过程中失控。针对 `POST /hooks/agent` 和 WebSocket RPC 接口，我实施了独立的 Hook Token 认证，并与 Gateway 主 Token 分离管理，确保外部脚本仅拥有最小权限。更重要的是，我将记忆存储职责从执行逻辑中彻底剥离：所有自动修改（如更新发布计划或策略参数）在执行前都会自动生成带时间戳的备份文件，并支持一键回滚。通过引入 `dry-run` 试运行模式和单周期修改上限（如每次进化最多修改 N 个文件），系统能够在不污染真实数据的前提下验证新策略。这种“备份 - 回滚 - 限流”的三重保护机制，有效化解了规模化自动化带来的执行安全风险，确保系统从“可记录”平稳演进为“可教学”的智能体。

## 今天的收获

- **接口分层决策**：对于一次性脚本或 CI/CD 场景，优先使用 `POST /hooks/agent` 或 `openclaw agent` CLI；对于定期执行任务，必须采用 `openclaw cron` 配合 `isolated` 会话模式以实现状态隔离。
- **会话隔离关键**：利用 `sessionKey`（如 `hook:<source>:<id>`）是保持上下文独立且支持多轮对话的核心，能有效避免不同自动化任务间的状态干扰。
- **安全底线原则**：任何自动化的写操作（Act 阶段）都必须前置备份机制，并配合 `dry-run` 预览和修改频率限制，确保系统在异常时可快速恢复。
- **进化闭环设计**：从被动的“规划 - 执行 - 跟踪”三阶段模型升级为 OADA 自主闭环，关键在于让 Agent 具备自动分析日志、决策优化方案并执行配置修改的能力。
- **预算控制意识**：为每个进化任务设定明确的时间（48-72 小时）和 Token 预算（50k-100k），并在超限时触发优雅降级和反思报告，防止资源无限消耗。
