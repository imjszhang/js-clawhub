# 从散乱笔记到自动光谱：知识棱镜工具架构落地实录

> Day 25 · 2026-02-24

随着 OpenClaw 学习笔记积累到 20 多篇，我发现“笔记越多，越难用”：想查核心概念或拼凑部署步骤，需要在不同日期的文档间反复横跳。时间线适合记录过程，却无法直接服务于教学与复用，这迫使我今天必须将“知识棱镜”方法论转化为可自动执行的工具架构。

## 三层架构与零依赖基石的确立

为了解决素材与产出的耦合问题，我严格定义了 Journal/Pyramid/Outputs 三层架构。Journal 层作为原始素材库，坚守“只增不改”原则，忠实按日期记录探索过程；Pyramid 层则承担结构化拆解的重任，分为分析轨（Atoms 提取、Groups 归组、Synthesis 收敛）和结构轨（Perspective 视角、SCQA 框架、Key Line 线索）；Outputs 层最终面向读者生成博客或教程。在技术选型上，我刻意坚持“零外部依赖”策略，核心库与独立 CLI 仅依赖 Node.js >= 18 的原生能力（如 `fetch` 调用 LLM），仅在 CLI 工具链构建技能包 zip 时引入 `archiver`。这种设计极大降低了安装门槛，确保了工具在任意环境下的生态兼容性。

## LLM 驱动的增量自动化管线

为了让散乱的时间线笔记自动转化为结构化知识，我设计并实现了由 LLM 驱动的三段式增量处理管线。第一阶段从 `journal/*.md` 提取最小知识单元 Atom，按月归档；第二阶段将新 Atom 跨文档归组为 Group，并提炼观点句；第三阶段收敛所有 Group 观点生成顶层 Synthesis 候选。整个流程遵循严格的“增量处理”与“幂等性”原则——只处理新增 journal，且同一素材多次运行不会产生重复 Atom。这并非基于规则的正则匹配，而是完全依赖 LLM 的语义理解能力，确保从白光到光谱的折射过程既智能又可靠。

## 双入口模式与无人值守运营

为了适配不同场景，项目采用了“双入口”设计：独立 CLI 通过 `npx js-knowledge-prism` 提供 init、process、status 等基础命令，适合脚本化调用；而 OpenClaw 插件则深度集成 Agent 对话，额外提供了 output 生成、agent-index 构建、多库注册（register/unregister）及 cron 调度等管理职能。两者共享同一套 `lib/` 核心模块，仅配置加载方式不同（.env vs openclaw.json）。插件注册了包括 `knowledge_prism_process_all` 在内的 14 个 AI 工具，支持注册多个知识库并通过 `setup-cron` 实现每小时自动批量处理。这种架构不仅实现了技能的动态发现与安装，更让系统具备了真正的无人值守运营能力。

## 今天的收获

- **架构分层是解耦关键**：严格分离 Journal（记录）、Pyramid（处理）、Outputs（产出），让原始素材的“乱”不影响最终知识的“序”。
- **零依赖提升鲁棒性**：核心逻辑坚持使用 Node.js 原生 API，避免第三方包带来的版本冲突与安装摩擦，是工具类项目的最佳实践。
- **增量与幂等是自动化基石**：LLM 处理成本高且耗时，必须设计“只处理新增”和“重复执行无副作用”的机制，才能支撑长期自动运行。
- **双入口适配多场景**：独立 CLI 满足 DevOps 需求，插件入口满足 Agent 交互需求，共享核心代码库实现了开发效率与用户体验的双赢。
