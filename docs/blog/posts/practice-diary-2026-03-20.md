# 消除人工换算：JS VI 系统内建微信封面自动化闭环

> Day 49 · 2026-03-20

今日的核心任务是解决公众号运营中的“视觉割裂”痛点：此前我们的通用海报尺寸缺乏微信专用命名，导致每次生成封面都需要人工换算像素，极易破坏品牌一致性。我决定在 `js-vi-system` 中直接内建微信专用模板与尺寸枚举，实现从 Prism 内容定稿到封面生成的无缝自动化。

## 定义专用尺寸枚举与静态约束

针对微信平台特殊的像素规范，我首先在 `templates/_shared/sizes.js` 的全局 `SIZES` 枚举中新增了 `wechat-cover` (900×383) 和 `wechat-thumb` (500×500) 两个键。此前团队只能使用 `a4` 或 `square` 等通用尺寸，运营人员必须自行计算 2.35:1 的横版比例，这不仅效率低下，还常因四舍五入导致上传后被微信裁剪。现在，通过 CLI 参数 `--size wechat-cover` 即可直接锁定标准规格，从源头消除了人工换算误差，确保所有输出素材严格符合信息流与转发卡片的展示要求。

## 构建独立模板目录与结构化元数据

为了适配直接导出位图的需求，我构建了独立的 `templates/wechat-cover/` 目录，其中包含 `render.js`、`meta.json` 及 `styles.css`。在元数据设计中，我明确声明了 `title`、`subtitle`、`tag`、`issue` 等结构化字段，以便 Agent 能直接将文章标题和栏目信息填入模板。关键决策在于默认禁用了动画（`animation.supported: false`），因为微信公众号封面需要静态的 PNG/JPEG 文件，这一约束确保了 `renderToHTML` 能正确内联样式并适配位图导出，避免了动态效果在静态截图中的渲染异常。

## 双模调用入口实现全链路闭环

为了让这套规范真正融入工作流，我提供了 CLI 命令行与 OpenClaw 插件双模调用入口。在独立 CLI 模式下，执行 `node bin/js-vi.js poster -t wechat-cover --size wechat-cover --scheme dark -f png` 即可一键生成；而在 OpenClaw 环境中，`vi_poster_generate` 插件同样支持指定 `template` 和 `size` 参数。这意味着当知识在 Prism 侧定稿后，Agent 可以直接调用同一套品牌规范生成封面，彻底避免了“文章在 Prism、配图在别处”的割裂感，实现了从内容创作到视觉产出的全链路自动化。

## 明确位图导出依赖与职责边界

在落地过程中，我进一步厘清了视觉系统与后续运营处理的职责边界。导出 PNG/JPEG/PDF 强依赖本机安装的 Chrome 或 Edge 浏览器（通过 `puppeteer-core` 调用），而 HTML 格式则无此依赖，适合用于快速校对版式。我明确系统仅负责像素精度与版式的一致性，对于微信后台可能要求的图片体积压缩，则交由运营人员在编辑器内后续处理。这种分工既保证了技术实现的稳定性，又保留了运营策略的灵活性。

## 今天的收获

- **专用枚举消除误差**：在尺寸系统中内建平台专用键（如 `wechat-cover`），比通用尺寸换算更能保障品牌视觉的标准化。
- **静态优先策略**：针对特定发布渠道（如公众号），在模板元数据中默认禁用动画，可避免渲染管线中的不必要复杂性。
- **样式内联机制**：`renderToHTML` 必须将模板目录 `meta._dir` 作为 `templateDir` 传入，才能确保外部模板的 CSS 正确内联，防止样式丢失。
- **职责边界清晰化**：自动化系统应聚焦于“像素与版式一致性”，将“体积压缩”等运营强相关策略剥离，保持系统轻量与专注。
