# 从“装双眼睛”到“浏览器操作系统”：JS-Eyes 2.6 的架构跃迁

> Day 92 · 2026-05-02

今天的主线任务是将 js-eyes 从单纯的“网页抓取插件”重新定义为"AI 的浏览器操作系统”，核心驱动力来自 2.6.x 系列版本中子技能独立升级通道（Harness 架构）的落地与安全防线的全面加固。

## 架构认知的重塑：从工具到基础设施

过去在 KL03 中，我给“龙虾”装上了 js-eyes，解决了它“看”浏览器的问题；到了 KL28，它学会了自动发现新技能。但直到今天处理 2.6.2 版本时，我才真正意识到架构性质的根本转变：这不再是一个功能堆砌的工具，而是一套标准化的交互基础设施。

目前的 js-eyes 2.6.2 已经构建了完整的五层抽象架构：底层是支持 Chrome 和 Firefox 的浏览器扩展与 native-host 原生消息通信；中间层是 server-core 与 protocol 构成的 WebSocket 服务端；上层则是涵盖 X、Reddit、YouTube、GitHub、微信、B 站等 11 个主流平台的技能层，并通过 openclaw-plugin 和 npm CLI (`js-eyes`) 进行统一调度。这种从“单点工具”到“操作系统”的认知跃迁，意味着我们不再关注增加了多少个抓取函数，而是关注如何为 AI 与浏览器的交互提供稳定、可扩展的标准化层。

## Harness 架构：解决“牵一发而动全身”的痛点

在之前的架构中，所有子技能都绑死在父版本号上，修复一个 Reddit 技能的 Bug 往往需要升级整个系统，这严重阻碍了技能生态的演进。今天落地的 2.6.0 版本核心突破在于引入了“子技能 Harness 机制”。

现在，11 个子技能各自拥有独立的版本升级通道和 `minParentVersion` 约束。每个技能作为一个独立的 Harness 单元，拥有自己的安全合约文件（`skill.contract.js`）和明确的边界。这意味着我们可以单独升级 `js-reddit-ops-skill` 而不影响其他平台技能，真正实现了“互不干扰”的生态化演进。这种设计让每个子技能有了自己的升级节奏，解决了旧架构中维护成本高昂的结构性难题。

## 实战验证：深度调研背后的稳定性支撑

架构的升级直接体现在了今天的实战场景中。我使用更新后的 `js-reddit-ops-skill` 对"AI coding agent"话题进行了深度调研，整个过程展示了新架构的效能：

1.  **搜社区**：调用 `reddit_search`，1 秒内按热度返回 10 条相关讨论。
2.  **拉详情**：通过 `reddit_get_post` 获取帖子详情，1.7 秒内完整拉取 334 条评论及 3 层深度结构。
3.  **跨社区对比**：快速切换上下文，对比 r/technology（3.5 万赞）与 r/LocalLLaMA（885 赞）对同一事件截然不同的讨论氛围。
4.  **展开深层**：利用 `reddit_expand_more` 一次性拉平"more"节点下的 500 条子评论，获取完整语境。

这一连串操作之所以能流畅运行且长时间不崩，得益于 2.6.1 版本对内存泄漏的修复。我们实现了 `register()` 方法的幂等化，确保热重载时先 teardown 再重建，并增加了指纹检测与 chokidar 噪声过滤，彻底解决了 `MaxListenersExceededWarning` 和文件描述符泄漏问题。

## 安全纵深：从被动扫描到主动防御

随着自动化场景的深化，执行安全成为重中之重。在 2.6.2 版本中，我们响应了 ClawHub 的安全扫描结果，将 5 个被标记的 flagged 调用点进行了模块化拆分。

更重要的是，我们实施了 READ（只读）、INTERACTIVE（交互）、DESTRUCTIVE（破坏性）三档安全分级策略，并新增了 `extraSkillDirs` 完整性校验功能（可选开启）。现在，通过运行 `js-eyes doctor --json`，我们可以输出系统的完整安全状态报告，将安全防御从被动修补转变为可度量的主动治理。这标志着系统从“可记录”向“可教学”演进过程中，建立了可信的执行边界。

## 今天的收获

- **架构解耦是生态化的前提**：通过 Harness 机制实现子技能独立版本化（minParentVersion + 独立合约），彻底解决了单体架构下“修一补十”的维护瓶颈。
- **稳定性源于细节治理**：长时间运行的自动化任务必须处理 `register()` 幂等化、热重载指纹检测及监听器噪声过滤，否则内存泄漏 inevitable。
- **安全需要分级与量化**：将操作权限细分为 READ/INTERACTIVE/DESTRUCTIVE 三档，并通过 `doctor` 命令输出量化安全状态，是建立系统信任的关键。
- **认知升级驱动技术演进**：从“给 AI 装眼睛”（解决登录态）到“给 AI 一套操作系统”（解决可控交互与进化），定位的转变决定了架构的厚度。
