# 教你的龙虾，用你的 flomo：从被动记录到主动思考的进化

> Day 77 · 2026-04-17

今天终于捅破了那层窗户纸：我们之前的系统解决了“龙虾够不到数据”的问题，但面对 flomo 里堆积如山的笔记，用户依然陷入了“记了但读不完”的困境。除非系统能替我们先读，否则知识积累只是数字垃圾。于是，`js-knowledge-flomo` 项目正式立项，目标直指让系统从“自生长”进化为“替你思考”。

## 直击痛点：从“人读笔记”到“系统替你思考”

在复盘 KL30 的自动维护流程时，我发现了一个被忽视的深层痛点：flomo 用户的核心困境从来不是“没记”，而是“记太多读不过来”。搜索一个关键词跳出 200 条结果，大多数人选择直接关闭窗口；明明写过某个观点，却完全不记得具体内容；笔记之间潜藏着巨大的关联价值，但人脑根本无法同时处理这些跨时空的信息。

KL27 通过 `wechat-cli` 解决了微信数据库的接入难题，让 OpenClaw 能拿到钥匙；而今天的 KL31 必须解决“龙虾读不完笔记”的问题。我的决策很明确：不再依赖人工阅读，而是构建一个自动化分析引擎。系统需要先替用户读完笔记，提炼出规律、情绪变化和隐藏关联，最后只把“洞察”交付给用户。这标志着我们的知识棱镜体系正式从“数据积累”跨越到“认知升维”。

## 架构落地：Node.js+SQLite+LLM 的五层模块化设计

为了实现这一目标，我设计了 `js-knowledge-flomo` 项目，采用轻量级但高扩展的技术栈：Node.js 18+ 作为运行时，SQLite 作为零依赖的本地缓存，配合 OpenAI 兼容 API 和 flomo 官方 MCP 协议。整个架构被划分为五个核心模块，确保逻辑清晰且易于维护。

在代码结构上，`cli/` 目录承载了核心逻辑，包括 `auth.js` 处理 OAuth 授权、`database.js` 管理 SQLite 缓存、以及 `processor.js` 作为 AI 加工引擎驱动七大分析功能。同时，项目创新性地扮演了双重角色：既是 MCP Client 接入 flomo 数据，又是 MCP Server 向 Cursor 或 Claude Desktop 提供工具能力。此外，独立的 `prompts/` 目录将提示词模板（如 `insight.txt`、`relate.txt`）与代码完全解耦，方便单独迭代优化；`src/` 目录则提供了本地 Web UI，让用户能在浏览器中直观查看标签树和洞察报告。

## 核心能力：七大 AI 分析功能挖掘隐藏价值

系统的灵魂在于其七大核心 AI 分析功能，它们将散乱的笔记转化为结构化知识。首先是**洞察发现**（`generateInsights`），系统默认拉取 50 条笔记缓存至 SQLite，利用 LLM 分析反复出现的主题、情绪态度的变化趋势，以及跨标签的隐藏关联，最终回答“你最近真正在关心什么”。

其次是**关联发现**（`findConnections`）与**观点演变**（`trackEvolution`）。前者强制 LLM 跨标签、跨时间寻找至少 3 组有意义的连接，推测用户潜意识里在思考的大问题；后者则按时间线标注关键转折点，明确指出观点从 A 变成 B 的具体证据。针对创作场景，**写作大纲**（`draftOutline`）基于真实的散落笔记生成结构化大纲，拒绝凭空捏造；**素材搜集**（`collectMaterial`）则结合关键词搜索与 flomo 的“相关推荐”接口，合并去重后返回高相关素材。

最后是针对标签体系的治理：**标签建议**（`suggestTags`）自动为无标签笔记推荐分类，而**标签审计**（`auditTags`）则深入分析标签树的重复、命名不一致及层级混乱问题，给出具体的合并或重命名操作建议。这七大功能共同构成了一个完整的认知辅助闭环。

## 安全底座：OAuth 授权与本地隐私优先原则

在规模化自动化场景中，安全是生命线。在接入方式上，我坚决放弃了逆向工程，选择 flomo 官方 MCP 协议，利用标准的 OAuth 授权流程确保凭证安全。数据存储方面，选用 SQLite 作为本地缓存，不仅轻量且支持复杂的 SQL 查询，更重要的是所有数据均落在用户本地环境。

对于最敏感的 AI 分析环节，系统强制走用户自建的 LLM API，确保原始笔记数据绝不流出用户环境。同时，我将所有 Prompt 模板独立存放在 `prompts/` 目录下，这种设计不仅实现了提示词工程与业务逻辑的解耦，也让用户可以随时审查和调整发送给 LLM 的指令，进一步掌控隐私边界。

## 今天的收获

- **痛点升级策略**：解决完“数据接入”后，必须立即转向“数据消化”，系统替用户阅读是打破知识堆积瓶颈的关键。
- **架构解耦设计**：将 Prompt 模板独立成目录（`prompts/`），实现了 AI 逻辑与代码逻辑的物理隔离，极大提升了迭代效率。
- **双重角色模式**：让同一个项目同时扮演 MCP Client（获取数据）和 MCP Server（提供工具），最大化了在不同 IDE 和 CLI 场景下的复用性。
- **隐私优先原则**：坚持“本地缓存 + 自建 LLM API + 官方 OAuth"三位一体，是在自动化场景中建立用户信任的唯一路径。
- **功能闭环思维**：从洞察发现到标签审计，七大功能覆盖了“输入 - 分析 - 输出 - 治理”的全生命周期，避免了单点工具的局限性。
